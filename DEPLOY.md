# Развёртывание платформы на сервере колледжа

Это веб-приложение на **Node.js** (Express + Socket.io). Фронтенд (HTML/CSS/JS)
раздаётся тем же сервером. База данных — это JSON-файлы в папке `backend/data`,
отдельная СУБД не нужна.

---

## 1. Что требуется на сервере

- **Node.js версии 18 или новее** (рекомендуется 20 LTS). Скачать: https://nodejs.org
  Проверить, что установлен:
  ```
  node -v
  npm -v
  ```
- Открытый порт (по умолчанию **3000**).

Больше ничего ставить не нужно — ни базы данных, ни PHP, ни Apache.

---

## 2. Что передавать

Передайте **исходники проекта** (zip или ссылку на GitHub).
**НЕ кладите** в архив папку `node_modules` — зависимости ставятся командой
`npm install`. Также не публикуйте файл `backend/.env` в открытом доступе
(в нём секретные ключи) — передайте его отдельно/лично.

Лучший вариант — клонировать с GitHub (всегда актуальная версия):
```
git clone https://github.com/Xarraket7/student-platform.git
```

---

## 3. Быстрый запуск

### Windows
```
cd путь\к\проекту\backend
npm install
npm start
```

### Linux / macOS
```
cd путь/к/проекту/backend
npm install
npm start
```

После запуска в консоли появится:
```
Server running on http://localhost:3000
```
Сайт открывается по адресу `http://АДРЕС_СЕРВЕРА:3000`.

---

## 4. Запуск в постоянном режиме (production)

`npm start` останавливается при закрытии терминала. На рабочем сервере
используйте **PM2** — он держит приложение запущенным и перезапускает при сбоях
и перезагрузке сервера.

```
npm install -g pm2
cd путь/к/проекту/backend
pm2 start server.js --name student-platform
pm2 save
pm2 startup      # выполнить команду, которую выведет pm2 (автозапуск при ребуте)
```

Полезные команды:
```
pm2 status                  # статус
pm2 logs student-platform   # логи
pm2 restart student-platform
pm2 stop student-platform
```

---

## 5. Файл `backend/.env`

Лежит в папке `backend`. Минимально нужен один параметр:

```
PORT=3000
JWT_SECRET=замените_на_длинную_случайную_строку
GOOGLE_CLIENT_ID=...   # только если используется вход через Google
```

- **JWT_SECRET** — секрет для входа пользователей. Если файла `.env` нет,
  приложение всё равно запустится со значением по умолчанию, но для рабочего
  сервера обязательно задайте свой секрет.
- **PORT** — можно изменить, если порт 3000 занят.

## ⚠️ Важные требования и рекомендации для администратора

Приложение использует **файловую базу данных** (JSON-файлы), а не отдельную СУБД.
Это просто и надёжно для масштаба колледжа, но накладывает несколько правил:

1. **Запускать строго в ОДНОМ процессе** (не в режиме кластера PM2).
   Команда `pm2 start server.js --name student-platform` из п.4 запускает один
   процесс — это правильно. **Нельзя** использовать `pm2 start ... -i max`
   (cluster): несколько копий начнут одновременно перезаписывать одни и те же
   JSON-файлы и испортят данные, а онлайн-чат перестанет работать корректно.

2. **Права на запись.** Серверу нужно право записи в папки `backend/data` и
   `backend/uploads`. Если выставить «только чтение» — сломаются регистрация,
   публикация постов и загрузка файлов.

3. **Регулярный бэкап `backend/data` и `backend/uploads`.** Раз база — это файлы,
   её сохранность зависит от диска сервера. Рекомендуется автоматическое
   копирование этих папок (например, ежедневно).

4. **Один сервер — одна копия.** Приложение не рассчитано на одновременный запуск
   на нескольких машинах (из-за файловой базы). Для колледжа это и не требуется.

> Файловой базы достаточно для внутренней платформы колледжа. Переход на
> настоящую СУБД (PostgreSQL/MongoDB) понадобится только при очень большой
> нагрузке (тысячи одновременных пользователей с активной записью).

## 6. Данные и резервные копии

Весь контент (пользователи, сообщества, новости, события, объявления) хранится
в JSON-файлах:
```
backend/data/*.json
```
Загруженные через сайт файлы (вложения в чат) — в `backend/uploads/`.

Для бэкапа достаточно скопировать папки `backend/data` и `backend/uploads`.
При обновлении кода **не перезаписывайте** эти папки, иначе потеряете данные.

Аккаунт администратора по умолчанию: `admin@college.kz` (см. `backend/data/users.json`).

## 7. Красивый адрес вместо `:3000` (опционально)

Чтобы сайт открывался по адресу вида `https://platforma.college.kz` без порта,
системный администратор может поставить **Nginx** как обратный прокси перед
приложением и подключить HTTPS-сертификат. Пример конфигурации Nginx:

```nginx
server {
    listen 80;
    server_name platforma.college.kz;

    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;        # для онлайн-чата (WebSocket)
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 8. Если что-то не запускается

- **`'node' не является командой` / `node: command not found`** — не установлен
  Node.js (см. п.1).
- **`Error: Cannot find module ...`** — не выполнен `npm install` в папке `backend`.
- **`EADDRINUSE: port 3000`** — порт занят: смените `PORT` в `.env` или
  освободите порт.
- **Чат не работает в реальном времени за Nginx** — не проброшены заголовки
  `Upgrade`/`Connection` (см. конфиг в п.7).
